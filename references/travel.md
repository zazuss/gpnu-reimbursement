# 比赛差旅报销流程

适用于广东技术师范大学。流程目标是证明任务、人员、行程、发票和付款对应；最终申报资格与金额以适用学校制度和财务审核为准。

## 一 收集与确认业务事实

收集赛事名称、城市、阶段、比赛或调试日期、队伍名单、每人实际往返日期、住宿入住退房日期、付款方式和已有审批材料。已有行程说明可以作为整理起点；赛事通知、参赛证明、出差审批等未提供时，列为可能需补充的依据，不把本资料集未出现的材料写成已经确认的必交清单。

同一人参加不同城市或阶段的比赛，分别建立赛事记录；支援人员单独标注身份与任务，不混为参赛者。个人延住与原团队住宿分开，预订日期、实际住宿日期、发票天数分别记录。

## 二 收集票据与支付证明

| 事项 | 基础材料 | 特殊情况下增加的对应信息 |
| --- | --- | --- |
| 出发 | 本人各段原始铁路电子发票／其他合规票据；订单与商户支付截图 | 集体购买订单、代购人、受益人名单、各人结算记录 |
| 返程 | 本人各段原始票据；订单与商户支付截图 | 改签／退票／补差价／退款凭证，与原票关系 |
| 住宿 | 原始住宿发票、订单与支付截图、实际入住人及期间 | 房间对应关系、房费付款人、合住者转账或未结算说明 |
| 附加项目 | 独立发票、订单项目明细、支付来源 | 按实际项目名称登记，与车票分开判断是否可报 |

按当前单据实际情况列出缺项，不一概认定已提供或已通过。铁路换乘每段都保留；“出发一张、返程一张”是直达情形的示例，不是多段行程只能收两张的限制。

微信昵称与真实姓名建立对照；群收款需展开到能辨认成员和付款金额的记录。只有群收款总额，不能据此认定每个人都付齐了。付款截图看清交易状态、日期、收付款对象、金额和交易标识，图片旁注明归属。

## 三 建立一份账本和两种查阅视图

先在账本中连接原票、订单、商户支付、内部转账、人员与赛事，再生成视图；内部可用唯一键，查阅页以中文材料名称显示。按事项将出发、返程、住宿的原票与商户付款放近；合并内部结算单独存放。需要按个人视图时按完整姓名建目录。每个赛事分别整理。

共享订单和发票可在两个目录提供副本或清楚的索引；提交压缩包时避免依赖易失效的快捷方式。每张副本说明对应费用、共享对象和唯一计账位置，无需给用户增加字母编号体系。

住宿目录以实际入住人命名，例如“张三＋李四”（示例姓名），不能把跨队合住机械写成整个队伍，也不要仅叫“房1”。保留房号作为辅助信息。

## 四 处理代购和合并转账

1. 代购人提供对商户的实际付款证明和相关订单，个人铁路发票按乘车人对应。
2. 同学提供给代购人的转账；代购人自己承担部分标“自付”，没有给自己的转账不算缺失。
3. 若一笔转账含往返费用，原交易只登记一次，用关联表说明覆盖的出发、返程及附加费用。无法可靠拆分时，保留“往返合并结算”，不要伪造两笔支付。
4. 存在多人结算不一致时，显示应结算、已转账、退款及差额；不能用均摊金额覆盖个人票价。
5. 同学之间的转账不与代购人对商户支付相加计算旅行总支出。

## 五 金额核对

用户最新明确的处理口径：**按实际净支付报销，以支付截图和原始发票为核心，发票与支付逐项一一对齐；发票金额可以高于对应实付，不能低于需报销的对应实付。** 票面、实际净支付和拟申报分列，不按较高票面多报，也不把少开发票当作资料齐全。

先按每项真实费用建立“支付截图／交易标识 → 原始发票／票号 → 对应净实付 → 拟申报”的核对行。核对人员、事项、期间、收款方或订单关系；金额相近不能代替业务对应。这里“一一对齐”指每笔每票均有明确归属与金额说明，不要求批量支付强拆为多张截图，也不要求优惠后的实付与优惠前票面强行相等。

一笔付款含多张发票，逐票列对应实付部分并核对合计等于该笔付款的相应范围；一张发票含多笔支付，列全关联支付并扣退款。同一支付和发票各只计一次。共享付款或优惠尚无可靠分配依据时保留批量范围，个人净实付及拟申报待确认，不擅自均摊。

同项有效发票高于净实付时保留票面，并说明已证实优惠等差异，报销按符合条件的净实付核算；低于需报销净实付时列出少开缺口，补充合规发票或核实处理后再确定申报，不能自动少报后标记核对完成。多开发票不表示可以虚构交易、要求不实开票或修改 PDF；纠错由商家按真实业务处理。

采用正数“优惠抵扣额”和正数“退款额”，公式里明确减去，避免反复取负。

```text
商户净支付 = 原成功付款合计 - 原路退款合计
订单预计净支付 = 车票或商品金额 + 独立附加费 + 其他已证实费用 - 已证实优惠 - 已证实退款
订单差额 = 商户净支付 - 订单预计净支付
票款差额 = 商户净支付 - 去重后关联发票总额
少开缺口 = MAX(同项需报销净实付 - 同项有效发票覆盖金额, 0)
个人结算差额 = 约定应承担金额 - 给代购人的净转账 - 已确认的其他结算
```

订单价若已经扣过优惠或退款，不再重复扣除。票价已经包含某项附加费时也不重复加；仅加独立、另计价且有证据的费用。

原订单含退款而原票已作废、红冲或被新票替代时，保留关系并剔除失效票的有效申报贡献。不要把原票和改签后新票都算一次。

发票与实付不等时，先排查服务费、优惠、退款、开票差异和日期范围，再列待确认项。拟申报金额以实际发生且符合资格、适用标准及有效票据覆盖的净支付核算；不可报或受限部分另列说明。不得用其他人、其他费用或其他赛事的多开票面掩盖某项发票不足，也不得用额外付款掩盖单项超报。该工作口径不替代学校制度和最终审批。

## 六 限额和特殊情况

按 [学校标准](policy.md) 选人员类别、目的地、日期和经费来源。住宿上限是核对上限，不能当作固定补贴，也不能把整间房费用复制到每个人名下。多人同住、入住期不同而缺少真实分摊依据时，只作整体费用和待确认标注。

非参赛支援、因游玩延迟返程、个人原因延住、提前返程但住宿仍按原期付款等，记录任务与个人活动的边界、退款情况和依据，拟申报部分另列待确认。保留原票，不自行改日期或假定可报。

经费来源未知时不套用横向经费例外。动卧、软卧、飞机或其他难以对应学生通常交通等级的票据，核对具体条款与审批依据，标明待确认；不单凭车次字母就判定符合。

## 七 提交前复核

- 每个赛事单独完整，姓名写全，每人往返所有路段都有原票或明确缺项。
- 事项汇总与个人对应表来自同一账本，票号和交易号去重；两种视图总额不再相加。
- Excel 有“出发、返程、住宿”文字行、清晰金额、小计和总计，截图在对应区块附近，区块之间留适当空行。
- 附加费、优惠、退款和凑分差额单列，有来源；未知原因仍标未知。
- 共享票据只计一次，内部转账与商户支付各算各的，微信昵称能对应实名。
- 发票原 PDF 可打开；金额单元格可编辑，不能只给表格图片；计算结果与原件逐项复核。
- 支付截图与发票逐笔逐票归属明确；每项需报销净实付有足额有效发票对应，少开缺口和未匹配支付／发票单列，不能只核对总额。
- 缺项、差异、未确认资格及超标准事项单列，拟申报总额与待审核总额分开。

材料交接对象按用户指定；发送、上传或正式提交需有该动作的授权。
